# Disjoint Set Union (DSU)

可以把 DFS 看作是查看一张地图（静态图）并找出所有岛屿（连通分量）的**一次性过程**。而并查集则像是一个高效的**实时**交通管制系统，能够以极快的速度处理“现在我们在这两个岛屿之间架一座桥（合并）”和“这两个点现在是否在同一个岛上（查询）”这类**动态变化**的问题。

```
静态链表：
出发元素 → 指向元素 (指向子节点)

1 → 3 → 4 → 5

| 1 | 2 | 3 | 4 | 5 |
| 3 |   | 4 | 5 | -1|


并查集相反，
指向元素 → 出发元素(指向父节点)
```



并查集（Union-find Sets，Disjoint Set Union，DSU）是一种非常精巧而实用的数据结构，它主要用于处理一些**不相交集合的合并和查询**问题。一些常见的用途有**求连通子图数量（图->并查集->树）、求最小生成树和求最近公共祖先（Tarjan离线算法）、判断无向图是否有环等**。

**并查集的基本**操作有三个：
- **makeSet(s)**：建立一个新的并查集，其中包含 s 个单元素集合。
- **unionSet(x, y)**：把元素 x 和元素 y 所在的集合合并，要求 x 和 y 所在的集合不相交，如果相交则不合并（即可以保证环必然不会出现）。
- **find(x)**：找到元素 x 所在的集合的代表（根），该操作也可以用于判断两个元素是否位于同一个集合，只要将它们各自的代表（根）比较一下就可以了。

## 原理
并查集的实现原理也比较简单，就是使用树来表示集合，树的每个结点就表示集合中的一个元素，**树根对应的元素就是该集合的代表**。

![](C:\Users\24940\Desktop\C++笔记\数据结构\images\并查集\并查集的树表示.jpg)

图中有两棵树，分别对应两个集合，其中第一个集合为 {a,b,c,d}，代表（根）元素是 a；第二个集合为 {e,f,g}，代表（根）元素是 e。

树的结点表示集合中的元素，指针表示指向父结点的指针，根结点的指针指向自己，表示其没有父结点。沿着每个结点的父结点不断向上查找，最终就可以找到该树的根结点，即该集合的代表（根）元素。

## makeSet
现在，应该可以很容易的写出 makeSet 和 find 的代码了，假设使用一个足够长的数组来存储树结点（很类似静态链表），那么 makeSet 要做的就是构造出如图的森林，**其中每个元素都是一个单元素集合，即父结点是其自身**：

![](C:\Users\24940\Desktop\C++笔记\数据结构\images\并查集\构造并查集初始化.jpg)

相应的代码如下所示，时间复杂度是 O(n)：

```cpp
#define MAXSIZE 500
int uset[MAXSIZE]; 
void makeSet(int size) {    
    for (int i = 0; i < size; i++) {
        uset[i] = i; //自己指向自己，为根结合点（代表）
    } 
}
```

## find
接下来，就是 find 操作了，如果每次都沿着父结点向上查找，那时间复杂度就是树的高度，完全不可能达到常数级。这里需要应用一种非常简单而有效的策略——路径压缩。

**路径压缩，就是在每次查找时，令查找路径上的每个结点都直接指向根结点**，如图所示。

![](C:\Users\24940\Desktop\C++笔记\数据结构\images\并查集\路径压缩.jpg)

### 没有路径压缩
```cpp
int find(int x) { //递归版本    
    if (x != uset[x])        
        x = find(uset[x]); //找到代表（根）   
    return x;
}

int find(int x) { //非递归版本  
    //依次向上找代表（根）
    while (x != uset[x]) {
        x = uset[x]; 
    }              
    return x;
}
```

### 有路径压缩
```cpp
int find(int x) { //递归版本1    
    if (x == uset[x]) return x;
    uset[x] = find(uset[x]);
    return uset[x];
}

int find(int x) { //递归版本2  
    if (x != uset[x]) {
        uset[x] = find(uset[x]); //路径压缩
    }               
    return uset[x]; //不能返回x，因为可能有2层，子结点必须返回父结点
}

int find(int x) { //非递归版本 
    int p = x, t;  
      
    //找到代表（根） 
    while (uset[p] != p) {
        p = uset[p]; 
    } 
        
    //处理所有x到根的结点
    while (x != p) {        
        t = uset[x]; //保存父结点
        uset[x] = p; //指向代表（根）
        x = t; //处理原父结点
    }    
    return x;
}
```

## unionSet
最后是合并操作 unionSet，并查集的合并也非常简单，就是将一个集合的树根指向另一个集合的树根，如图所示。

![](C:\Users\24940\Desktop\C++笔记\数据结构\images\并查集\并查集的合并.jpg)

这里也可以应用一个简单的启发式策略——**按秩合并**(按**高度**排序）。该方法使用秩来表示树高度的上界，在合并时，**总是将具有较小秩的树根指向具有较大秩的树根**。简单的说，就是总是将比较矮的树作为子树，添加到较高的树中。**为了保存秩，需要额外使用一个与 uset 同长度的数组，并将所有元素都初始化为 1**。

```cpp
//额外使用一个与 uset 同长度的数组，并将所有元素都初始化为 1
vector<int> urank;
urank.resize(n, 1);

//针对find没有路径压缩的情况
void unionSet(int x, int y) {
    x = find(x); //找到所在的集合的代表（根）
    y = find(y); //找到所在的集合的代表（根）
    
    //名字rank在std中存在，所以最好用其他替换，如height, urank
    if (rank[x] > rank[y]) {
        uset[y] = x; 
    } else {
        uset[x] = y;   
        
        //更新秩
        if (rank[x] == rank[y]) rank[y]++;  
    }
}
```
除了按秩合并，并查集还有一种常见的策略，就是**按集合中包含的元素个数（或者说树中的结点数）合并**，将包含结点较少的树根，指向包含结点较多的树根。这个策略与按秩合并的策略类似，同样可以提升并查集的运行速度，而且省去了额外的 rank 数组。

这样的并查集具有一个略微不同的定义，**即若 uset 的值是正数，则表示该元素的父结点（的索引）；若是负数，则表示该元素是所在集合的ROOT（即树根），而且值的相反数即为集合中的元素个数**。相应的代码如下：

```cpp
#define MAXSIZE 500
int uset[MAXSIZE]; 
void makeSet(int size) {    
    for (int i = 0; i < size; i++)         
        uset[i] = -1; //指向自己，且树只有一个结点
}

int find(int x) {  //递归版本  
    //x为根结点
    if (uset[x] < 0) return x;    
        
    uset[x] = find(uset[x]); //路径压缩
      
    return uset[x];
}

int find(int x) {   //非递归版本   
    int p = x, t;
     
    //找到代表（根）
    while (uset[p] >= 0) {
        p = uset[p];                     
    }
    
    while (x != p) {        
        t = uset[x]; //保存父结点
        uset[x] = p; //指向代表（根）
        x = t; //处理原父结点
    }    
    return x;
}

void unionSet(int x, int y) {    
    x = find(x); //找到所在的集合的代表（根）
    y = find(y); //找到所在的集合的代表（根）
    
    //保证环必然不会出现
    if (x == y) return;  
     
    if (uset[x] < uset[y]) { //abs(x) > abs(y)      
        uset[x] += uset[y]; //更新总结点数
        uset[y] = x; //将y合并到x，即y指向x
    } else { //abs(x) <= abs(y)         
        uset[y] += uset[x]; //更新总结点数
        uset[x] = y; //将y合并到x，即y指向x
    }
}
```
**如果要获取某个元素 x 所在集合包含的元素个数，可以使用 -uset[find(x)] 得到。**

**并查集的空间复杂度是 O(n) 的**，这个很显然，如果是按秩合并的，占的空间要多一些。**find 和 unionSet 操作都可以看成是常数级的**，或者准确来说，在一个包含 n 个元素的并查集中，进行 m 次查找或合并操作，最坏情况下所需的时间为 O(mα(n))，这里的 α 是 Ackerman 函数的某个反函数，在极大的范围内（比可观察到的宇宙中估计的原子数量 10^80 还大很多）都可以认为是不大于 4 的。具体的时间复杂度分析，请参见《算法导论》的 21.4 节 带路径压缩的按秩合并的分析。
